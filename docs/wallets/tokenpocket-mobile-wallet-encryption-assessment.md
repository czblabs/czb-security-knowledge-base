## App Version Signals

Useful non-secret signals include:

- TokenPocket app version, download source and approximate creation or migration date.
- Phone model, operating-system version and whether the original device is available.
- Whether TokenPocket still opens, lists the wallet account, shows a public address or displays an error prompt.
- Whether the wallet was created inside TokenPocket or imported through seed phrase, private key, keystore or hardware wallet.
- Whether multi-chain accounts, biometric unlock, transaction password or backup reminders were used.

## Safe Technical Notes

TokenPocket cases often involve confusion between the local transaction password and the key material that controls a self-custody wallet. The local password may protect encrypted wallet data, but the seed phrase, private key, keystore file or passphrase is the core control material. App versions and migration history can influence what evidence remains on a device.

Safe public documentation may explain encrypted app data, account import methods and backup-state assessment. It should not include extraction recipes, brute-force procedures, tooling modes or device bypass instructions.

## Recovery Feasibility Signals

Assessment may be realistic when:

- The old phone, encrypted app data, wallet metadata or backup file still exists.
- A seed phrase, private key, keystore, hardware wallet or paper backup may exist.
- The app still shows the account name, public address, chain list or repeated error prompt.
- Public-chain evidence can connect the requester to the wallet timeline.

Assessment is usually weak when there is no old device, no backup material and only a public address is known.
